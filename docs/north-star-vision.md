# North Star Vision

## The Core Insight

**This was never a "trial canceller." It's the first working organ of a personal autonomous operations layer.**

The trial system is not the product — it's the **training ground**. Trials have crisp deadlines, clean win/lose signals, and immediate financial feedback. They are the perfect domain to prove the autonomous loop works before pointing it at everything else.

## What We've Actually Built

### 1. A Closed-Loop Autonomous Agent

**The Loop:** Discover → Prioritize → Track → Act → Prove → Learn

This is the hard part of *every* useful agent system. We've built it:
- **Discovery:** Email scanner finds trial expiration notices, subscription renewals, billing alerts
- **Prioritization:** Arbitrage finder calculates ROI, ranks by value, identifies high-impact targets
- **Tracking:** KV ↔ Notion sync maintains system of truth with human oversight
- **Action:** Cancellation orchestrator executes multi-tier strategy with dark pattern detection
- **Proof:** Verification step confirms cancellation actually succeeded (not just "submitted")
- **Learn:** Service playbooks improve with each successful cancellation

**Why This Matters:** Most agents can act but can't learn. We've built the reflex arc that compounds.

### 2. A Self-Improving Knowledge Base

**Service Playbooks as Moat:**

Every service Devin successfully cancels becomes permanent knowledge:
- **Cancellation method:** API vs one-click vs RPA vs manual
- **Dark patterns:** What UX tricks to avoid, which buttons to click
- **Timing:** When the service bills, how long before to cancel
- **Verification:** How to confirm cancellation actually stuck
- **Failure modes:** What breaks, how to retry, when to escalate

**Six months from now:** You don't have a script. You have a **verified, self-improving map of how hundreds of services actually work** — which is genuinely valuable and very hard to recreate.

**Why This Matters:** Knowledge compounds. Each cancellation makes the next one easier and more reliable.

### 3. A Two-Stack Platform Architecture

**Cloudflare + Azure = The Right Tool for Each Job:**

- **Cloudflare:** Fast, cheap, edge automation (cancellation orchestrator, Workers, KV)
- **Azure:** Client-facing AI Runbook Operator (Functions, Logic Apps, Key Vault, Storage, API Management)

**Why This Matters:** We've accidentally designed exactly the architecture a real automation company runs on. The trial system is our **internal dogfood** — the thing that proves the Runbook Operator works before a single customer touches it. Best founders ship the tool they use themselves.

- **Devin:** Builds the worker, implements the logic, runs the code

- **You (architect):** Make the calls, set priorities, define the vision

**Why This Matters:** This is the workflow everyone's *trying* to figure out — and it's already running in this thread. We're not coding a feature; we're operating a team.
